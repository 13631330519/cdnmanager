API 接入说明

URL 刷新与文件上传外部接口接入文档，登录后可直接参考。

公共说明：API Key 获取

本文中的两类接口均使用同一套签名鉴权方式，优先使用“域名绑定的项目/环境 API Key”。

  1. 进入「项目管理」页面，创建项目与环境。
  2. 在对应项目或环境中生成 API Key（推荐优先使用环境级 Key）。(找管理员获取)
  3. 在「域名管理」中绑定域名到同一项目/环境，确保请求中的 domain 能解析到正确的密钥。
  4. 如果项目或环境已配置独立 API Key，不能再使用公共默认 Key，否则服务端会返回 403。

适用范围：URL 刷新接口与文件上传外部 API 均共用这一获取方式。

1. URL 刷新接口：POST /api/refresh_url

接口： POST /api/refresh_url

Content-Type： application/json

字段 必填 说明
url 是 要刷新的 CDN 资源 URL
timestamp 是 Unix 秒级时间戳
signature 是 HMAC-SHA256 签名

签名规则

message = url + timestamp
signature = hmac.sha256(EXTERNAL_API_SECRET, message).hexdigest()

示例请求

curl -X POST https://cdn-manager.example.com/api/refresh_url \
  -H 'Content-Type: application/json' \
  -d '{
    "url": "https://cdn.example.com/assets/logo.png",
    "timestamp": 1720000000,
    "signature": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
  }'

说明：

  • 请求中的 domain 必须绑定到已存在的项目/环境；签名使用解析后的项目/环境 API Key。
  • API Key 的获取方式见上方「公共说明：API Key 获取」。
  • 服务器会记录本次 URL 刷新任务并返回刷新结果。

2. 文件上传外部 API 接入说明

客户端直接向对象存储上传，服务端只负责签发 PUT URL、校验和可选 CDN 刷新；上传与刷新使用相同的 HMAC 签名鉴权模式。

核心接口

方法 路径 用途
POST /api/upload/init 创建上传 Job，批量签发小文件 PUT URL
POST /api/upload/presign 补签未签发成功的小文件 URL
POST /api/upload/complete 确认上传完成并触发可选 CDN 刷新

签名说明

signature = HMAC-SHA256(secret, message).hexdigest()

# init
message = {domain}{timestamp}

# presign / complete
message = {domain}{job_id}{timestamp}

接入前准备

  • 先按上方「公共说明：API Key 获取」中的步骤获取项目/环境级 API Key。
  • 随后绑定域名到同一项目/环境，并确保存储目标和域名配置一致。

上传流程

  1. 调用 /api/upload/init 创建 Job，并拿到 upload_url。
  2. 使用 PUT 请求将文件直接上传到对象存储，并读取响应头中的 ETag。
  3. 调用 /api/upload/complete 上报 etag 与 job_id。
  4. 如设置 refresh_after，服务器会在完成后执行 CDN 刷新。

常见限制

  • 单批 init 最多 1000 个文件；补签单次最多 50 个。
  • 单文件 PUT 上限约 100 MB；大文件请走后台文件存储页或拆分。
  • 时间戳有效窗口通常为 ±300 秒，签名过期会被拒绝。
  • 外部 API 不提供 Job 进度查询，需自行跟踪 job_id。
